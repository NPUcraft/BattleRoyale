# BattleRoyale 部署说明

本文记录 **1.0.0-rc.11** 的部署方案（2026-10-01），目标为 Paper **26.2 build 129** / Java **25**，仓库为私有 **NPUcraft/BattleRoyale**。正式安装与验收状态以本轮 release 回执为准；以下不预先宣称已上线。

最终安装工件的 SHA-256、隔离验收结果、部署时间和回读检查以对应 [GitHub release](https://github.com/NPUcraft/BattleRoyale/releases) 的附件与正式部署回执为准。源码中的功能说明不作为上线证明。本文不包含面板凭据、玩家资料或私有备份路径。

## 名称与升级边界

- 插件及数据目录：`BattleRoyale`、`plugins/BattleRoyale/`。
- 命令：`/br`，完整命令 `/battleroyale`；权限：`battleroyale.*`。
- Java 包：`com.npucraft.battleroyale`；安装工件：`battleroyale-1.0.0-rc.11.jar`。
- 专用大厅示例：`battleroyale_lobby`；比赛与维护维度分别使用 `battleroyale_game`、`battleroyale_maintenance` 命名空间。

rc.8 不保留旧命令别名，不自动识别旧插件目录、数据库 schema 或持久命名空间。已有服务器必须在停服备份后显式迁移，不能通过把新旧 JAR 同时放入插件目录完成升级。迁移应保留玩家 UUID、经济账户和 SQL 业务记录、地图种子、世界 UUID、大厅建筑及既有中文展示实体 UUID。

安全部署顺序为：确认无人在线、无活动房间或待恢复事务；正常停服；备份完整插件数据、数据库文件组和受影响世界数据；在独立副本完成改名并校验 SQL 完整性及业务行摘要；只安装本次验证的工件；启动后核对版本、配置、地图、经济与大厅。失败时保持停服，使用经过校验的完整备份恢复，不混合新旧目录重试。

## 三房间与地图方案

部署示例使用同一个 `Survival-Main` 地图模板、地图 ID `survival`：Solo 每队 1 人、4 人开局、上限 24；Duo 每队 2 人、8 人开局、上限 24；Squad 每队 4 人、16 人开局、上限 32。三个房间均为 60 秒开局倒计时与 60 秒落地 PvP 保护。该三房配置不是自动写入已有服务器的迁移。

rc.11 暂定可玩范围为 **X、Z 各 -5000 至 5000**，以原出生点 X=951、Z=862 周边的 **X=751–1151、Z=662–1062** 配置命名区域 `spawn`（出生点附近）。矩形是圈心候选范围，不是安全区边界；候选范围加最大初始半径须完整位于可玩区域内。按 1–4/5–8/9–16/17–32 名开局玩家选择 400/600/1000/1500 格边长，后续目标同比缩放且圈心继续随机。四阶段共 430 秒，不含倒计时、准备与飞机投放。先冻结初始战区，再复制初始圈外扩 512 格所涉及的完整 region、entities、poi 及关联外置区块；模板种子不变，维护操作仍使用完整副本。该规则不代表整张地图已预生成，也不能代替地形与出生点校验。

等待/倒计时阶段用 `/br vote` 或排队指南针对候选区域投票，界面显示实时票数和范围，可改票或撤回，离开清票。每名玩家每张地图各有一票，比赛先选地图再结算该图；最高票获选，平票或无人投票时随机，随后在获选矩形内随机取圈心。当前方案仅提供出生点附近一个区域；需要真正的多区域选择时可增加合法候选，不能与同一地图的旧版 `points` 配置混用。

部署用初始装备为石剑、弓、16 支箭、8 个面包和皮革胸甲，使用当前 Paper 原生物品序列化。地面物资、空投表和出生规则应通过 `/br admin config validate` 与 `/br admin map validate survival --deep` 校验，具体语义见[配置说明](CONFIGURATION.md)与[玩法说明](GAMEPLAY.md)。

## 大厅与玩家语言

大厅地板中心示例为 `(0, 200, 0)`、半径 32。已完成的 READY 建筑不重新施工；新增或更新展示内容只处理插件自己的实体。四份原中文门牌保留，新增四份英文门牌；排行榜使用两份语言文本、一个讲台展示和一个交互实体，总计十二份自有实体。玩家只看到匹配语言的五份文本；重启按持久标记复用与去重。

客户端 `zh` 系列使用中文，其它及未知玩家语言使用英文；控制台保持中文。默认标题和房名提供双语，自定义文字及玩家名称不翻译。原版物品名由 Minecraft 客户端语言文件显示。侧栏每房一行名称、人数、状态或倒计时，三房加在线人数及操作提示共五行；不再展示开局门槛、还需人数或分隔行。

大厅排行榜展示真实 Rating TOP 8、击杀与胜场，每约 30 秒异步刷新。无记录时显示空榜；右键讲台打开个人数据。不会为展示插入演示玩家。

## rc.8 玩法变更

马匹默认每 15 秒尝试生成一匹，每局累计上限 16，配置允许 1–64；取鞍、击杀和正常恢复不会重置额度。安全地形不足时可以少于上限。

空投原生信标仅提供速度 I，无第二效果。范围是半径 24 格的三维球体，仅作用于同局、同世界、在线且存活的非观战成员。原生 80-tick 刷新时给予 100 ticks（5 秒）的效果，不覆盖更强或持续更久的已有速度；离开范围或清理信标后，插件授予的效果自然到期。预告、固定落点、保证物资及临时方块恢复规则见[玩法说明](GAMEPLAY.md)。

## 经济与证据边界

本轮不更换经济依赖：CoinsEngine **2.7.0**、nightcore **2.15.0**、Vault **1.7.3-b131**、PlaceholderAPI **2.12.3**。已有经济账户与配置应保持；部署用 `coins` 货币及新账户 100 金币规则不等于插件默认赠币。上游版本声明仍不包含 26.2，详见[经济兼容性](ECONOMY.md)。

[验证记录](VERIFICATION.md)只陈述已确认的本轮证据。此前里程碑与 rc.3–rc.7 的日志、旧名称和备份位置保留在私有历史归档，不将其路径机械改名后用作本轮部署证明。真实客户端语言显示、骑乘、多人完整对局与跨代理链路须独立验收。


## rc.11 物资与开局部署差异

地图原生容器改用 `loot-tables.yml` 中独立的 `native-basic` 表，只提供基础生存物资，不随机附魔、不受自然区/建筑区品质升级。部署时需一并添加该表；只替换 JAR 不会覆盖旧文件中的 40% 概率或旧表。显式配置的容器 LootPoint 继续原有区域品质与普通抽取规则。

```yaml
auto-containers:
  enabled: true
  loot-table: native-basic
  chance: 0.15
  min-rolls: 1
  max-rolls: 2
  max-containers-per-tick: 16
```

野外仍请求 320–400 个分散候选点，区域单点尝试配置保持 10，受安全地形及全局 800 次候选尝试、45 秒预算限制。准备改为最多 8 个在途区块请求，每 tick 最多检查 8 个已完成候选、发起 8 个请求，共享 2 毫秒软预算；这是调度限制，不是实测耗时承诺。准备 BossBar 显示物资已完成/总点数，最终跳过也计入完成，重试不增加分母。安全地形不足时允许少生成；停止后等待已有请求结束，不再补发。

准备时不生成物品实体。补给点继续使用彩色粒子环和近处音效，存活玩家靠近 4 格且有视线后认领生成；领取文件先落盘，每点最多八堆，单 tick 最多生成四点，停止或恢复不重复发放。此处运行时发放上限与准备阶段的八个候选检查是不同预算。

保留每区块 16 柱/最多 48 块的区域品质缓存，人工地表比例阈值为 25%，只影响野外补给和显式配置的容器点。自然区保留基础战斗资源和少量功能物品，建筑区提高铁装、药水等权重，并保留低权重单颗钻石。普通装备仍使用安全的低级附魔；空投、怪物掉落和金币配置保留。

飞机落地识别使用脚部真实碰撞面，支持台阶、楼梯，不依赖客户端接地标志；临时鞘翅回收与原胸甲恢复保持原流程，物资安全地形要求不变。

本轮配置差异为 `loot-tables.yml` 的基础容器表与概率、`zones.yml` 的命名圈心区域；此前已调整的地图有效可玩范围继续保留。若已有地图元数据，须同步更新其中的可玩范围，不能只改 `maps.yml`。保留原模板地形、大厅、房间、账户和经济依赖；上线前在一致副本上验证配置与地图。当前构建、自动化测试与独立 Paper 原生验收已通过，正式部署以 release 回执为准。
