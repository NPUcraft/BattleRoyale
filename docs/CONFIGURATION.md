# 配置版本与文件

主配置集现在 config-version: 2：config.yml、rooms.yml、maps.yml、zones.yml、loadouts.yml、loot-tables.yml、lobby.yml、ranking.yml、cosmetics.yml。

无版本视作 legacy v1。启动先预检所有存在文件的语法/版本，再备份待迁移文件到 config-backups/<timestamp-uuid>/，逐文件原子替换版本化数据；失败回滚已写文件，备份保留。未知更高版本拒绝加载，绝不向下覆盖。跨多个配置文件与断电不是单一事务，但每个替换原子、每份原件有备份，重启可识别已完成版本并继续；YAML 序列化可能规范化格式和注释。

`/br admin config validate` 读取全部配置与地图内容，不发布运行状态、不迁移、不保存；`backup` 保存主配置集（不包含数据库与模板）。地图编辑器统一元数据使用独立 format-version=1/revision。首次 Save 前仍兼容 map-data/<id>/loot.yml。

config.yml 控制存储、恢复、大厅世界、外观经济来源、Zone UI、战斗与离线窗口；rooms.yml 引用地图池/loadout/zone；maps.yml 指向模板和基础区域；zones.yml 定义人数分档及缩圈阶段；loadouts.yml 保存原生物品；loot-tables.yml 定义物品权重、自动容器物资和阶段空投；ranking.yml 定义 Rating、Kill Score、周期时区与缓存；lobby.yml 定义大厅建筑、保护、登录行为和菜单；cosmetics.yml 定义纯视觉外观和价格。

Paper 26.2 / Java 25 版本使用 Paper 的统一 level 维度目录。`runtime-worlds.directory` 仍保留并校验为旧配置的相对路径，但不再控制运行目录；比赛固定使用 `Server.getLevelDirectory()/dimensions/battleroyale_game/`，编辑器和维护固定使用同级 `battleroyale_maintenance/`。模板路径仍相对于插件数据目录，格式要求见 [MAPS.md](MAPS.md)。`lobby.world` 填已加载世界名称，不填文件系统路径。

map-maintenance.pregeneration.max-concurrent-chunks 默认 8（执行时限制 1–32）。维护粒子、地面采样与生成总量均有硬上限。debug 默认 false。

请在停服状态编辑地图文件；在线变更通过内置编辑器，以 revision 原子发布。手改后通过 validate/reload 或重启重新加载；不能对正在运行的 Session 热修改规则。

## rc.8：语言、侧栏、马匹与信标增益

插件固定按客户端 locale 选择语言：`zh` 系列使用中文，其它（包括未知）使用英文，无需玩家命令切换。控制台保留中文。默认菜单标题、物品说明、房名与外观名提供双语；管理员自定义文字及玩家名称原样显示，不进行机器翻译。Minecraft 原生物品名仍由客户端原版语言文件呈现。

大厅侧栏每个房间仅一行，三房加在线人数和操作提示共五行；仍按 `sidebar.page-seconds` 分页。共享大厅全息按中英两组分别向对应玩家显示，locale 改变后刷新。

空投信标在半径 24 格的三维球形范围内，为同局、同世界、在线存活的非观战成员提供速度 I；原生信标每 80 ticks 刷新一次，效果持续 100 ticks（5 秒）。无第二增益，也不覆盖更强或持续更久的已有速度效果。离开范围或信标清理后，插件授予的效果自然到期，不主动删除其它来源的速度效果。

### 马匹、材料与空投附魔

`loot-tables.yml` 顶层新增马匹设置，与 `auto-containers`、`airdrops`、`mob-loot` 并列；整段缺失时采用以下默认值：

```yaml
horses:
  enabled: true
  max-per-session: 16
  interval-seconds: 15
  max-attempts: 24
  min-distance: 64
```

只在 `RUNNING` 的比赛副本中生成成年、已驯服、带鞍且没有专属主人的原生马。每批最多成功生成一匹，批次结束后再等待 `interval-seconds`；每批最多检查 `max-attempts` 个候选，始终只保留一个异步区块请求。地点位于当前安全区，要求平坦的 3×3 安全支撑、三格空气净空、无液体/危险方块和附近生物，且与以前生成点至少相距 `min-distance`。地形不适合时可以不足配置数量，不会强行覆盖地形。

`max-per-session` 是每局累计生成额度，允许 1–64；间隔允许 5–600 秒，尝试次数 1–128，距离 8–256 格。生成前先记录位置和会话身份；马匹死亡、被移除、离开安全区或失去马鞍不会释放额度，也不自动补鞍。账本和原生实体状态随世界保存，正常重启恢复后继续使用；账本缺失、损坏或会话身份不匹配时停止新增，避免追补旧比赛。停用及清理会释放生成器自己的区块票据，已有马匹随比赛副本处理，不遍历删除自然马。

新安装的 `basic` 和 `airdrop` 表加入木头、圆石、石头、铁锭、金锭、煤和低权重钻石；实际权重与数量均由 `loot-tables.*.entries` 控制，已有表不会被资源自动覆盖。木头可用于制作木板，材料可以按原版规则合成和使用。

普通物资继续采用下节的 35% 单项低等级附魔。rc.7 空投随机装备以 80% 概率进入专用附魔抽取，空投保证装备则必定进入；进入后按强化 70%、稀有 25%、极品 5% 选择档位。强化主附魔通常为 II–III，稀有在原版上限附近随机并增加耐久，极品使用原版最高等级并追加该物品可接受的兼容附魔。一级封顶的附魔仍只有 I；不使用超限、诅咒或互斥附魔。5% 是进入专用抽取后的条件概率，随机装备整体抽中极品的概率约为 4%，非装备不会因此变成附魔物品。这些概率是内置规则，无单独 YAML 字段。

默认中文菜单、侧栏和大厅标题使用“大逃杀”；英文项目名及聊天前缀保留 `BattleRoyale`。已有 `lobby.yml` 自定义标题继续保留，可手动修改 `titles` 与 `sidebar.title`。rc.8 统一使用 `BattleRoyale` 插件名、`plugins/BattleRoyale` 目录、`battleroyale.*` 权限和 `/br`（完整命令 `/battleroyale`）。没有旧命令别名或自动读取旧数据目录的兼容分支。本节描述配置和行为，不代表真人骑乘、烟花渲染或远端部署已经验收。

## rc.6：开局人数、原生物资与怪物奖励

房间开局倒计时使用 `countdown-seconds: 60`。三种模式的 `min-players` 分别配置为 `solo: 4`、`duo: 8`、`squad: 16`，对应至少四支满编队的人数门槛，`team-size` 分别为 1、2、4。已有房间配置不会被资源自动覆盖；修改已有服务器时同时核对房间上限和圈人数分档。人数掉回门槛以下会取消并重置倒计时；管理员强制开局命令仍可绕过人数门槛。

普通地面物资、配置容器、自动容器和怪物奖励共用普通原生生成规则。适合附魔的装备每次生成默认有 35% 概率获得一项适用的安全附魔，等级为 I–II；快速装填和致密仅 I。普通规则不会生成诅咒、堆叠多项附魔或给食物/药水附魔；空投从 rc.7 起使用上节的独立强化规则。此概率是内置规则，不是 `auto-containers.chance` 或 `mob-loot.chance`；这两个字段各自控制容器是否生成和怪物是否追加奖励。`minecraft:elytra` 作为物资配置会被拒绝，所有保证物资也不含鞘翅。

`loot-tables.*.entries[].item` 除 `minecraft:` 原生物品外，支持以下 11 个原生物品预设，不依赖自定义物品插件：

```text
battleroyale:invisibility_potion
battleroyale:splash_invisibility_potion
battleroyale:fire_resistance_potion
battleroyale:splash_fire_resistance_potion
battleroyale:healing_potion
battleroyale:splash_healing_potion
battleroyale:harming_potion
battleroyale:splash_harming_potion
battleroyale:poison_potion
battleroyale:splash_poison_potion
battleroyale:combat_firework
```

药水均为 I 级：隐身 30 秒、防火 60 秒、治疗/伤害为瞬时、剧毒 8 秒。普通与喷溅版本使用同一基础效果；喷溅实际作用时长/强度仍遵循原版命中距离规则。它们使用无额外长效的水瓶基底、原生自定义效果和客户端可翻译的原版名称，不会同时附带完整时长的原版药水效果。战斗烟花是原生烟花火箭，飞行强度 0、仅一颗小球烟花星，既可直接使用也可装入弩，不是无爆炸星的空壳火箭。

`loot-tables.yml` 顶层新增以下配置，与 `auto-containers`、`airdrops` 并列：

```yaml
mob-loot:
  enabled: true
  loot-table: basic
  chance: 0.35
  min-rolls: 1
  max-rolls: 1
  max-drops-per-session: 64
  per-player-cooldown-seconds: 10
```

仅 `RUNNING` 比赛中仍存活、在线且没有待恢复/冻结状态的玩家，在本局比赛世界直接击杀自然生成的敌对怪物时可追加奖励；玩家归属的投射物可计入。只接受 `NATURAL` 和 `CHUNK_GEN` 来源，刷怪笼、试炼刷怪笼、刷怪蛋/发射器、繁殖、分裂、转化及自定义生成等来源排除，玩家生成实体会被持久标记。宠物、被动动物、玩家、离线替身和无直接玩家来源的环境击杀不计入。

合格击杀默认有 35% 概率追加一次抽取，每名玩家每 10 秒最多尝试一次，概率未中也消耗本次尝试冷却。每局最多 64 次成功奖励批次；`max-drops-per-session` 计成功批次，不是单个物品。`chance` 范围 0–1，抽取次数 1–3，成功批次上限 1–256，冷却 1–300 秒；每次抽取最多 8 个物品且遵守原生最大堆叠，最多三堆，不改变原版掉落和经验。缺少整段时优先选择 `basic`，没有则使用首张已加载表；没有表时关闭。开启但引用不存在的表会拒绝加载。

来源标记、比赛计数与玩家冷却写入实体/世界/玩家的持久数据，正常保存、区块重载、重登和比赛恢复继续保留，不通过重登重置刷取额度。它们与世界和玩家存档一同保存，不提供突然断电时的跨文件事务保证。以上为配置规则说明，不表示已部署或通过真人战斗验证。

## rc.5–rc.7：安全区导航与增强边缘

`config.yml` 的新安装资源使用以下数值。已有文件不覆盖：缺少 `navigation` 段时默认开启、每 5 ticks 更新；缺少 `colored` 时默认开启。已有的视距、间距、高度和粒子上限继续按原文件执行。

```yaml
zone-ui:
  navigation:
    enabled: true
    update-interval-ticks: 5
  bossbar:
    enabled: true
    update-interval-ticks: 5
  particle-wall:
    enabled: true
    colored: true
    particle: END_ROD
    interval-ticks: 5
    view-distance: 80
    spacing: 1.5
    vertical-spacing: 1.5
    height-below-player: 4
    height-above-player: 12
    max-particles-per-player: 400
```

行动栏显示相对玩家朝向的八方向箭头与水平距离，rc.7 不再显示圈心 X/Z。目标为下一圈，最终阶段为当前安全区；箭头始终指向目标圈中心，圈外用红色显示到目标圈边界的最短距离，圈内用绿色显示到中心的距离。靠近中心时显示圆点；箭头方向和圈外距离各自表达“朝中心走”与“还需多远进圈”。有已公告或尚有物资的有效空投时，追加最近空投的金色方向与距离；信号取消、到期、取空或清理后撤下。BossBar 增加下一圈面积，按 `(2 × halfSize)²` 计算。导航不占物品槽，观战、退出比赛和清理时撤下；更新间隔允许 1–40 ticks，BossBar 和粒子墙可分别关闭。

粒子墙仅在玩家附近采样；各条可见边轮流分配预算，优先绘制最近处和视线附近高度。`colored: true` 使用红色尘埃与配置粒子交错显示，红色与亮色共用 `max-particles-per-player` 上限，不叠加额外一层；设为 `false` 后全部使用 `particle`。`particle` 仍只接受无需额外数据的 Paper 粒子，例如 `END_ROD`，无需将它改成 `DUST`。粒子墙不设置全局或玩家虚拟 WorldBorder，不改变碰撞边界。

视距允许 1–256 格，水平间距 0.25–256 格，垂直间距 0.25–64 格，上下高度各 0–64 格，每玩家每次粒子硬上限为 1–1000。提高密度会增加发往每名参赛者的粒子量；新安装数值是 80 格视距、1.5 格间距、下 4/上 12 格、最多 400 个。整个 `zone-ui` 段缺失时仍兼容旧默认墙面数值（64 格、水平 2.5 格、下 3/上 6 格、300 个），并开启新导航和颜色。修改后在无活动比赛、维护及未完成清理的状态执行 `/br reload`，影响后续比赛。

## rc.5–rc.7：自动容器物资与空投

以下配置位于 `loot-tables.yml` 顶层，与 `loot-tables:` 并列。自动容器默认使用 `basic`；新安装的空投使用随资源提供的 `airdrop` 表。缺少新配置段的旧文件在存在物资表时默认开启，优先使用已有 `basic`，没有 `basic` 则使用已加载的首张表；没有任何表时默认关闭。显式开启并引用不存在的表会拒绝加载，不会静默生成空箱。

```yaml
auto-containers:
  enabled: true
  loot-table: basic
  chance: 0.9
  min-rolls: 2
  max-rolls: 5
  max-containers-per-tick: 16
airdrops:
  enabled: true
  loot-table: airdrop
  min-rolls: 8
  max-rolls: 12
  fall-seconds: 8
  max-attempts: 24
  marker-seconds: 120
```

自动容器发现仅处理本局初始圈内已加载区块，每 tick 最多检查 16 个候选，不为扫描整张地图强制加载区块。支持普通/陷阱箱、双箱、木桶、潜影盒、漏斗、发射器和投掷器；熔炉、酿造台等专用槽位不参与。默认每个合格空容器有 90% 概率抽取 2–5 次，使用所选表的物品和权重，抽取次数由本段覆盖；这不是承诺每箱固定件数。

非空容器、地图显式配置的物资点、玩家放置的容器和带空投标记的箱子不接受自动补货。双箱按一个容器处理并标记两个物理箱体；是否成功抽中都会保存本局处理标记，拿空、拆分、卸载重载或恢复比赛不会重新抽取。标记随区块和容器保存；恢复保留现有物品，仅继续发现尚未处理的合格容器。旧比赛副本缺少自动生成会话标记时不追补，以免把玩家已经使用过的存储当作新箱子。

`chance` 允许 0–1，`min-rolls/max-rolls` 为 1–128 且最小不大于最大，后台候选预算为 1–256/tick；仍受物资表每批最多 4096 个物品的限制。自动容器功能不增加地面物资区域或生成次数。正式 `survival` 地图的地面密度、装备和表内容另见 [BattleRoyale 部署记录](BATTLEROYALE.md)，不要把部署专用数值视为通用资源默认值。

rc.6 起每轮空投会提前预告：等待缩圈剩余不超过 60 秒时开始寻找安全落点，位置随机选在下一圈内；最终圈使用当前圈。安全落点确认后广播固定 X/Y/Z，并显示金色光柱，预告期间没有可领取容器。预告后完整等待 60 秒才开始下降；即使首轮等待本来不足 60 秒，也不会缩短这段预告。候选区块准备可能使投放晚于缩圈开始，空投不会暂停缩圈。预告时长固定 60 秒，没有独立配置字段。

公告后的坐标和高度保持不变，开始下降和落地前均重新检查落点；变得不安全、被占用或离开当前安全区时取消并通知，不会悄悄换点。默认以木桶显示实体下降 8 秒，落地后才生成可打开的木桶；降落与落地继续广播同一坐标。光柱在落地后默认最多持续 120 秒，物资取空会提前撤下；光柱撤下不删除箱子。

rc.7 光柱采用真实信标、黄色玻璃与 3×3 铁块底座，放在空投附近的安全位置。需要天空无遮挡、底座可安全替换且没有容器或附近生物；安装前保存原方块。信标与底座不能被玩家拆取或修改，不提供信标效果，也不会成为刷材料来源。取消、信号到期、箱子取空、比赛结束或恢复清理时，只有仍属于本局且与插件放置状态一致的方块才还原，保留外部改动；清理同步释放相关区块票据。恢复只清除持久记录中的遗留信号，不重新发空投。真实信标仍受服务端区块加载、客户端渲染距离和遮挡影响，不保证整张地图无限距离可见。

每箱先放入两份固定保证物资：一件必定附魔的钻石武器/护甲或弓，以及一个不死图腾；钻石装备/弓在七种候选中随机选择。保证装备与随机装备的附魔档位见 rc.7 说明。随后再按空投表抽取默认 8–12 次，这两份保证物资不占 `min-rolls/max-rolls` 次数。保证物资先占槽，27 格满后只截断后续随机物资，不挤掉保证物资，也不将溢出物品扔到地上。

每轮最多尝试 24 个落点，找不到安全地面则取消该轮并通知玩家，不强行覆盖地形或容器。`fall-seconds` 为 1–30 秒，`max-attempts` 为 1–128，空投抽取次数为 1–27，`marker-seconds` 为 0–600 秒（0 关闭持续光柱）；箱子容量有限，拆堆后超出 27 格的部分不会额外掉落。

每轮先把会话与轮次写入比赛副本的原子票据，再生成空投；写入失败时停止该局空投，比赛其他部分继续。恢复不会补发已经认领或已经开始缩圈的轮次，也不续播尚未落地的动画；尚未开始的后续轮次正常继续。运行中跨过多个阶段时按未处理轮次依次调度，每次只处理一个空投。此去重规则不代表数据库与世界文件构成同一事务，完整恢复边界见 [恢复说明](RECOVERY.md)。

## rc.5：结算倒计时与提前回大厅

`config.yml` 的 `match.winner-showcase-seconds` 继续控制结算展示时长，默认 60 秒。进入 `ENDING` 后，比赛世界中的玩家会看到“返回大厅倒计时”行动栏；倒计时结束自动清理并返回大厅。`/br leave` 允许在结果已经确定并完成持久化、恢复与存储状态正常后提前恢复原大厅状态；结果仍在保存时会提示稍后重试。

rc.7 获胜烟花使用多色大球与爆裂效果，每次庆祝分三波、间隔 8 ticks，单波最多 8 发、同局同时存活最多 32 发。这些上限内置，没有新增配置字段；庆祝烟花的专用身份用于拦截其对玩家和其他生物的伤害。比赛清理会取消剩余波次并移除自有烟花，物资中的普通战斗火箭不受这条庆祝免伤规则影响。

提前返回只恢复该玩家并撤下比赛界面，不删除本局参赛身份、队伍历史或已确定的结果。房间成员身份和跨房间加入限制保留至本局正常结算与清理结束，不能借提前返回立即加入另一局。`PREPARING`、`STARTING`、`RUNNING` 中的存活参赛者仍不能用此命令逃离；已淘汰玩家退出观战继续走原有恢复流程。

以上为 rc.5 配置与行为说明，不表示已部署到远端或完成真人端到端验收；具体部署与验证状态分别见 [BattleRoyale](BATTLEROYALE.md) 和 [验证记录](VERIFICATION.md)。

## rc.4：颜色样式与聊天

插件消息、菜单、BossBar、淘汰播报和全息使用统一 Adventure 组件：青蓝用于品牌和标题，浅灰用于正文，金黄用于命令、参数和数字，绿色、红色、橙色分别表示成功、错误和警告。普通文字内容保持不变；配置中的名称、玩家名字及消息不会作为 MiniMessage 标签或颜色代码执行。此配色由插件内置，不需要额外依赖。

`config.yml` 增加以下开关，缺失时默认均为 `true`：

```yaml
chat:
  format-enabled: true
  connection-messages: true
```

`format-enabled` 控制普通玩家聊天格式，显示为青蓝玩家名、金色 `»` 分隔和浅灰正文。`connection-messages` 控制加入/离开服务器提示的中文分色。两项仅在监听器创建时读取，修改后必须重启服务器，`/br reload` 不会更新这两个开关。关闭普通聊天格式不会关闭插件自身的消息颜色。

聊天监听器只装饰显示组件，不改消息原文、接收者或已取消状态，也不异步查询房间/世界状态。专用聊天插件可在更高事件优先级覆盖该渲染器；已有聊天插件负责格式时，可将这两项设为 `false`。玩家输入 `<red>` 等标签会原样显示，不会由 BattleRoyale 执行格式或命令。

等待或倒计时中的房间成员会在快捷栏最后一格（第 9 格，内部槽位 8）看到红床“退出房间”，右键退出排队。该按钮保存被临时占用槽位的原物品；离队时恢复，开局前也会先恢复再保存大厅快照和应用比赛装备。准备开始后按钮不再提供退出能力，也不会成为比赛 Loadout 或可放置的床。`/br leave` 仍可使用；此功能没有单独的配置开关。

已有 `READY` 大厅在初始化时刷新插件自有四块全息标牌的文字和颜色，不重铺建筑，不移除其他插件或管理员的标牌。上述内容为配置及行为说明，不作为远端部署或真人操作验收记录。

## rc.4：大厅实时计分板

`lobby.yml` 支持以下配置；旧文件没有 `sidebar` 段时也使用这些默认值：

```yaml
sidebar:
  enabled: true
  title: 大逃杀
  page-seconds: 8
```

侧栏复用大厅每秒一次的主线程更新，读取实时房间人数、状态和倒计时；只向处于大厅世界、可使用大厅或正在等待/倒计时的玩家展示。比赛准备、观战、地图编辑、死亡和状态恢复期间不展示。每个房间一行，每页最多五个房间，加在线人数与一行提示最多七行，三房共五行；更多房间按 `page-seconds` 轮播，页码合并到提示行。不显示分隔行、开局门槛或还需人数。翻页间隔须为 2–60 秒，标题须为 1–32 个字符的单行普通文本，不解析 MiniMessage 标签。

计分板使用独立对象和固定条目，更新内容时不反复重建；右侧的排序数字隐藏。退出大厅、退出服务器、插件关闭或重新配置时恢复原有计分板。如果其他插件主动切换玩家计分板，本次大厅停留期间不反复抢回。大厅显示期间不会合并原计分板的 Team、名牌或其他 objective；需要保留外部插件这些显示时，可将 `enabled` 设为 `false`。这些配置在允许重载的状态执行 `/br reload` 后生效。

## rc.3：专用中文大厅

通用默认配置关闭自动建造。确认专用大厅世界后，在 `config.yml` 设置 `lobby.world: battleroyale_lobby`；由 Paper 加载该世界，主存档可使用 `server.properties` 的 `level-name=battleroyale_lobby`。三处世界名称必须与实际环境一致，不要把目录路径填入世界名称。

以下是专用大厅的部署示例，不代表已经应用到任何远端服务器：

```yaml
# lobby.yml，保留 config-version、titles 和 items 原有段落
structure:
  enabled: true
  world: battleroyale_lobby
  center: { x: 0, y: 200, z: 0 }
  radius: 32
  blocks-per-tick: 1200
  clear-existing-blocks: true
protection:
  enabled: true
  allow-admin-build: false
login:
  return-to-lobby: true
```

`center.y` 是地板高度，出生点在中心上方一格。蓝图为约 65×65 的八角广场，三个带屋顶的入口分别使用房间 ID `solo`、`duo`、`squad`；中央讲台打开房间菜单。半径固定为 32；施工上限为每 tick 100–4000 个方块，默认 1200；只修改中心相对 x/z ±32、y -3 至 +10 的蓝图区域。缺少整个 `structure` 段的旧配置不会自行施工。

`clear-existing-blocks: false` 要求施工区域为空气；开启后，首次施工先保存原有非空气方块的 BlockData，再允许清理天然地形。箱子等 TileState 方块仍拒绝覆盖，需先转移其内容和方块。原方块备份 `plugins/BattleRoyale/lobby-structure-original.blocks.gz` 是施工备份，不代替完整世界备份；没有自动回滚地图命令。

`lobby-structure.properties` 绑定世界 UUID、世界名、坐标、蓝图版本及施工状态。`READY` 后重启检查出生空间、刷新插件自有全息并恢复大厅功能，不会重铺地板或覆盖装修；`BUILDING` 可在原始备份和现有方块核对通过后继续。标记不符或检测到无法解释的改动时停止建造并保留文件。不要通过删除标记来强行重建；移动大厅或更换世界前先停服并备份、核查现有建筑和备份。日志 `LOBBY_READY` 表示该次大厅初始化完成。

保护涵盖建筑和装饰、右键实体、伤害、饥饿、物品丢弃/拾取、爆炸/流体/生长、投射物和药水。等待与倒计时房间中的玩家仍受保护，跌出或离开平台会回到中心。比赛维度和地图编辑维度不受大厅保护影响。管理员装修时可临时设置 `protection.allow-admin-build: true` 并在允许重载的状态执行 `/br reload`；只有 `battleroyale.admin` 玩家可绕过施工/交互限制，完成后关闭。`protection.enabled: false` 会关闭保护和回拉，请仅在明确需要时使用。

`login.return-to-lobby: true` 在恢复完成后的大厅循环将普通玩家送到中心、重新发放中文快捷物品；循环间隔约一秒。启动恢复期间冻结登录玩家的移动和物品操作。活动比赛的合法重连、待恢复背包、观战和地图编辑优先处理，防止登录大厅覆盖权威玩家状态。READY 校验失败不会阻塞比赛重连处理。

## rc.3：三房间与 10,000 格随机地图

部署可使用 `solo`、`duo`、`squad` 三个房间，中文名称分别为“单人竞技”“双人组队”“四人小队”，`team-size` 分别为 1、2、4，共用 `maps: [Survival-Main]`。rc.6 开局最少人数更新为 4、8、16，对应至少四支完整队伍的人数；人数上限、出生距离和初始圈人数分档应一起核对。服务器 `max-players` 是所有世界合计上限，不等于各房间上限之和，修改房间不应覆盖运营者已设置的服务器人数限制。

示例地图注册（另需合法模板及对应物资/元数据）：

```yaml
maps:
  Survival-Main:
    display-name: 自然生存主地图
    directory: maps/Survival-Main
    playable-area:
      min-x: -5000
      max-x: 5000
      min-z: -5000
      max-z: 5000
```

10,000×10,000 是可随机选择战区的平面范围，不是每局安全区边长，也不是每局重新生成一个随机种子。先生成一次随机种子的普通 Paper 26.2 模板并停服导出，各局保留其种子和生成设置，在该范围内随机选择本局初始安全区。已有 `map-data/<id>/metadata.json` 时，其可玩区域和显示名称是权威配置；应通过地图编辑器更新，不能只改 `maps.yml` 后假定生效。

比赛开始先锁定人数、队伍和初始安全区，再复制与“初始圈 + 四周各 512 格缓冲”相交的完整 512×512 region 文件；`region`、`entities`、`poi` 使用一致范围，保留这些 region 引用的全部外置 `.mcc`。生成设置及其他维度数据继续保留。此范围复制只用于新比赛，编辑和预生成维护仍复制完整模板，恢复继续使用原比赛副本。缓冲是复制优化，不是世界边界；新到达且模板未复制的区块可能按种子生成，因此重要手工内容和玩法应位于初始圈及其缓冲内。不会为每局复制整张 10,000 格地图，也不会自动预生成整张地图。

上线前在停止修改的模板上执行地图校验，按实际出生规则抽查地形，并检查物资覆盖；先用少量玩家验证三种房间，再按容量增加负载。模板、大厅、比赛副本和数据库分开核对，备份时保持停止或一致快照状态。


## rc.10 野外补给与区域品质

`LootArea` 的范围、抽取表和点数仍控制候选点；安全地形准备有 800 次/45 秒总预算。候选点不预生成 Item 或 Display 实体。存活参赛者在 48 格内看到最近三处补给的彩色粒子环和闪光柱，24 格内每 8 秒听到一次最近点轻响；走到 4 格内且无方块遮挡时开启。自然区青绿色、建筑区金色。每点最多 8 堆，单 tick 最多生成 4 点；普通玩家和使用掉落物雷达者在开启前都收不到这些点的 Item 实体。客户端关闭粒子或音效会影响提示可见性，这不是通用反作弊。

计划和领取状态存入比赛副本内 `battleroyale-ground-supplies.json`，先原子认领再生成。正常走开不会吞掉已认领补给；区块临时卸载或落点被挡会等待安全条件恢复，不主动加载区块。停止比赛后不再生成。崩溃恰好发生在认领落盘与实体保存之间可能少发，恢复不会重发以防复制。旧比赛没有该文件时不补建新点。

```yaml
region-quality:
  enabled: true
  built-threshold: 0.25
  natural-table: region-natural
  built-table: region-built
```

此段属于 `loot-tables.yml`，两种表也须定义在 `loot-tables` 下。没有该段的旧配置保持原表。每区块首次加载/开局已加载时检查 4×4 地表柱、每柱最多向下三块；16 柱中至少 25% 含人造物即为建筑区。工作台、箱子、耕地、木板、砖等计入，树木、原石矿物、泥土和普通石头不计入。结果按会话保存在区块 PDC 并缓存，不主动加载邻区块，不因后来放方块而更新。恢复缺少旧标记时保守视为自然区。自动容器、配置容器和野外点更换物品权重来源，原抽取次数保持；怪物和空投继续用原表。

## rc.10 人数缩放与开局中心

`zones.yml` 的 `stage-reference-half-size: 750` 表示阶段目标按本局初始半径 / 750 同比缩放；省略或填 0 保留旧绝对目标。默认人数分档的半径为 200/300/500/750（边长 400/600/1000/1500），默认四阶段共 430 秒，不包含房间倒计时、准备和飞机投放。每阶段等待至少 60 秒，为原有一分钟空投预告留出时间。

以下仅为部署示例，放在 `profiles.default` 内。`survival` 必须是已配置的地图 ID；可列多个点随机选择，抖动半径可为 0。所有点连同最大可达初始圈和抖动必须完全落在地图有效边界内。

```yaml
initial-centers:
  survival:
    jitter-radius: 0
    points:
      - {x: 951, z: 862}
```

这些点仅决定开局整体范围位置。后续每次缩圈仍随机选取内嵌中心，最终圈不锁在出生点；恢复使用已保存的初始大小，不按剩余人数重算。
